1. Scegli cosa mostrare con @if

Il control flow decide quali elementi creare nel template. Prova prima una condizione, poi due rami alternativi: cambia lo stato e osserva il risultato.

Messaggio {{ showMessage ? 'visibile' : 'nascosto' }}. Accesso simulato {{ isLoggedIn ? 'attivo' : 'disattivo' }}.

@if (showMessage) {

Questo elemento esiste solo quando la condizione è vera.

} @if (isLoggedIn) {

Benvenuto! Stai vedendo il ramo @if.

} @else {

Accedi per continuare: stai vedendo il ramo @else.

}

È una simulazione locale: il pulsante cambia un booleano, senza autenticazione reale. Quando nascondi il primo messaggio, Angular rimuove il suo elemento; non applica soltanto uno stile.

3. Gestisci più casi con @switch

Scegli uno stato del contenuto. Ogni caso mostra un messaggio diverso; il caso sconosciuto attiva il ramo di riserva @default.

@switch (publicationState) { @case ('draft') {

Bozza: puoi modificare il contenuto.

} @case ('review') {

In revisione: controlla il contenuto prima di pubblicarlo.

} @case ('published') {

Pubblicato: il contenuto è visibile.

} @default {

Stato sconosciuto: scegli uno stato valido.

} }

4. Cambia l'aspetto con i binding

Qui l'elemento rimane nel DOM: cambia una classe o una proprietà di stile. Questi sono binding nativi di Angular, non le direttive NgClass e NgStyle.

Binding [class.active]: classe {{ isActive ? 'attiva' : 'disattiva' }}.

Binding [style.color]: colore {{ usePrimaryColor ? 'primario' : 'del testo' }}.

Classe {{ isActive ? 'attiva' : 'disattiva' }}; colore {{ usePrimaryColor ? 'primario' : 'del testo' }}.

5. Riusa un comportamento con una direttiva

appLessonHighlight è una vera direttiva di attributo locale: riceve un booleano e applica una classe all'elemento ospite. Puoi riutilizzarla su più elementi senza duplicare il binding della classe.

Questa nota mantiene il suo contenuto e il suo significato. Evidenziazione {{ isHighlighted ? 'attiva' : 'disattiva' }}.

Evidenziazione {{ isHighlighted ? 'attiva' : 'disattiva' }}. Il testo descrive lo stato anche senza percepire il colore.

Le condizioni leggono proprietà del componente. I pulsanti cambiano quelle proprietà; Angular aggiorna il template. Copia un esempio alla volta nel tuo componente.

Il nucleo delle operazioni sulla lista: crea un nuovo array, conserva gli ID e genera un ID nuovo quando aggiungi. La demo completa aggiunge anche ripristino, pulizia del campo e annunci di stato.

Tre strumenti, tre responsabilità

  • Control flow integrato: @if, @for e @switch decidono la struttura del template. Non richiedono import da CommonModule.
  • Binding nativi: [class.active] e [style.color] aggiornano direttamente una classe o uno stile. Per una singola classe o proprietà sono sufficienti.
  • Direttive di attributo: aggiungono un comportamento riutilizzabile. NgClass e NgStyle sono direttive di Angular per insiemi di classi e stili; richiedono un import. appLessonHighlight è il nostro esempio personalizzato, importato dal componente.

Identità e casi alternativi

Il nome di un elemento può cambiare o ripetersi: usa un ID univoco e stabile in track. Riordinare non deve creare nuove identità. @empty gestisce una collezione vuota; @default gestisce un valore che non corrisponde ad alcun caso. @switch confronta con uguaglianza stretta e non richiede break.

Prova a prevedere il risultato: cosa resta dopo aver nascosto un elemento con @if? E dopo avergli tolto una classe? Nel primo caso viene rimosso dal DOM; nel secondo conserva struttura e contenuto.

Se arrivi da un progetto precedente

Nei tutorial storici puoi incontrare *ngIf, *ngFor e [ngSwitch]: sono le direttive della sintassi precedente. In questa lezione scriviamo nuovi template con il control flow integrato; non serve memorizzare entrambe le sintassi per iniziare.

Se conosci React, puoi paragonare una condizione a un'espressione condizionale e track a una key stabile. È un confronto facoltativo: Angular usa un proprio template compilato.
