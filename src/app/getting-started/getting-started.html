Un componente è una piccola parte dell'interfaccia

Angular collega una classe, che conserva i dati e i comportamenti, a un template, che descrive cosa mostrare, e agli stili, che ne definiscono l'aspetto. Il riquadro qui sotto cambia con le tue azioni: non serve modificare file per fare il primo esperimento.

Prova: scrivi «Benvenuta, Ada!», premi «Aggiungi 1» due volte e attiva «Evidenzia scheda». Vedrai cambiare rispettivamente testo, numero e aspetto. Il reset ripristina tutte e tre le cose. Le modifiche sono locali a questa pagina.

Testo del componente

{{ message || 'Scrivi un messaggio' }}

Conteggio locale: {{ count }}

Stile: {{ highlighted ? 'evidenziato' : 'normale' }}.

{{ status }}

Che cosa hai cambiato?

  • Classe: message contiene una stringa, count un numero e highlighted un booleano, cioè vero o falso. Sono campi dell'istanza: un'altra istanza dello stesso componente avrebbe i propri valori.
  • Template: le doppie graffe mostrano i campi, le parentesi tonde ascoltano le azioni, le quadre collegano un valore a una proprietà. La lezione Data Binding approfondisce queste direzioni.
  • Stili: una classe CSS aggiunta quando highlighted è vero cambia il riquadro; il messaggio e il conteggio non vengono modificati dallo stile.

Tre file, una responsabilità per file

Questo è un esempio completo di componente, suddiviso in tre file adiacenti, pronto per questo progetto con il suo tema e i suoi helper SCSS. Non è un editor live: i blocchi spiegano la demo e puoi copiarli nel tuo progetto.

welcome-card.ts: configurazione e stato

Il decoratore Component associa la classe ai file HTML e SCSS. Il selector app-welcome-card è il nome con cui il padre la inserisce nel proprio template. In Angular 22 i componenti sono standalone per impostazione predefinita: non serve un NgModule.

welcome-card.html: vista e azioni

La demo usa gli stessi tre campi. Il suo contatore chiama un metodo per annunciare il risultato; nell'esempio minimo l'assegnazione è direttamente nell'evento click.

welcome-card.scss: aspetto locale

Il suffisso highlighted è una variante della classe della scheda. I colori arrivano dal tema Material dell'applicazione; space, rem e radius sono helper del file condiviso globals. Per portare l'esempio in un altro progetto occorre fornire anche questi helper o sostituirli con valori CSS. Il CSS dei componenti è normalmente incapsulato: non occorre cambiare lo stile di tutte le sezioni del sito.

Due tipi di import da non confondere

L'import TypeScript in cima al file rende un simbolo disponibile al codice. L'elenco imports dentro Component rende disponibili componenti, direttive e pipe nel template. Qui abilita mat-form-field, matInput e i pulsanti Material.

Questo componente padre completo importa WelcomeCard e usa il suo selector. Puoi collocarlo nello stesso progetto e renderlo raggiungibile tramite la configurazione dell'applicazione.

Leggere la classe senza conoscere tutto TypeScript

TypeScript aggiunge controlli sui tipi a JavaScript. Da message = 'Ciao, Angular!' deduce il tipo string, da count = 0 il tipo number, e da highlighted = false il tipo boolean. Assegnare un numero a message sarebbe un errore di tipo.

Un metodo è una funzione della classe. Nel metodo, this.message indica il campo di questa istanza; nel template basta scrivere message. Il tipo void dopo un metodo significa che non restituisce un risultato. updateMessage riceve un Event e verifica che la sua origine sia un input prima di leggere value. Questa demo usa campi normali: non richiede Signals.

Dove guardare in questo progetto

  • src/main.ts avvia l'applicazione; src/app/app.ts e app.html compongono la struttura principale.
  • src/app/app.config.ts registra i provider dell'app; src/app/app.routes.ts associa indirizzi e pagine.
  • Ogni cartella di lezione contiene classe, template, stili ed eventuali test di comportamento.
  • src/styles.scss e src/styles/ raccolgono tema e regole condivise; public/ contiene file statici.
  • I file spec.ts verificano interazioni e risultati. Un file non diventa componente soltanto per il suo nome: conta la configurazione Component.

La vista ha un ciclo di vita

Angular costruisce l'istanza, imposta gli input e chiama ngOnInit se è presente. Aggiorna poi la vista in risposta alle modifiche. Quando il componente esce dalla vista, lo distrugge: è il momento di rilasciare le risorse create manualmente. Chiudere una spiegazione in questa lezione non distrugge la demo.

Frammento opzionale per una classe: importa DestroyRef e inject da Angular core. Un timer manuale continua a funzionare finché non lo cancelli; onDestroy registra la pulizia. Questo frammento non viene eseguito dalla demo e non aggiorna una vista: stampa soltanto tick in console.

Non avviare timer o richieste dentro un'espressione del template. Per le sottoscrizioni studierai anche async pipe e takeUntilDestroyed, che collegano la pulizia alla durata della vista.
